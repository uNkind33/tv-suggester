# AI Rules — Simple Architecture (React + TypeScript)

Ты пишешь код в проекте по правилам Simple Architecture. Полный список правил — [ARCHITECTURE.md](ARCHITECTURE.md), описание проекта — [README.md](README.md). Ниже — то, как их применять. Если задача требует нарушить правило, не нарушай его молча: остановись и скажи об этом.

## 1. Слои

| Слой | Файл | Что делает | Чего НЕ делает |
|---|---|---|---|
| View | `Name.tsx` | Только JSX. Получает props, вызывает `usePresenter`, раскладывает результат по разметке | Не форматирует, не считает, не фильтрует, не обращается к store и API, не склеивает классы |
| Presenter | `usePresenter.ts` | Берёт данные из store/хуков, готовит их для View (форматирование, флаги, обработчики) | Не содержит JSX, не ходит в сеть напрямую |
| Логика | хуки (`hooks/`, `useX.ts`), чистые функции (`lib/`) | Загрузка, debounce, фильтры, пагинация | Не знает про компоненты |
| Инфраструктура | `api/`, `store/` | Сеть, глобальное состояние | Не знает про React-компоненты |

Допустимо в View: условный рендер, `map` по готовому массиву, передача props. Любое `?.slice`, `join`, `toFixed`, шаблонная строка с данными, тернарник для className — это логика, её место в presenter.

## 2. Файлы и папки

- Файл — не больше 120 строк (проверяет oxlint `max-lines`). Не помещается — раздели, а не сжимай.
- Один компонент — одна папка: `Name/Name.tsx`, `Name/Name.module.css`, при необходимости `Name/usePresenter.ts`.
- Дерево папок повторяет иерархию компонентов: дочерний компонент лежит в папке родителя. Вложенность не ограничена.
- Где лежит компонент:
  - нужен одной ветке → внутри этой ветки;
  - нужен нескольким веткам → в ближайшую общую `components/` (общие для всего приложения — `src/components`);
  - импортируется ровно в одном месте → в `components/` НЕ кладётся, а лежит рядом с единственным потребителем.
- `usePresenter.ts` — только если есть что готовить. Пустой presenter не создавай. Увидел логику в View — вынеси её в presenter.
- Инфраструктура в корне `src`: `api/`, `store/`, `lib/`, `hooks/`.
- Стили — CSS Modules рядом с компонентом (`Name.module.css`).

## 3. Именование

- Компонент и его файл: `PascalCase`, `export default`. Props — `interface Props` в том же файле.
- Presenter: `export function usePresenter(...)`, принимает только то, что нельзя взять из store (props родителя).
- Хуки логики: `useXxx`, имя по смыслу (`useShows`, `useDebouncedValue`), а не по технике.
- Константы: `UPPER_SNAKE_CASE` и экспортируются там, где определены (`DEBOUNCE_MS`).
- Общие типы объявляй один раз и импортируй (`import type`). Не дублируй union-типы по файлам.

## 4. Данные и асинхронность

- Запросы к API — только через функции в `api/`; компоненты и presenter их не вызывают.
- Загрузку делай хуком (`useAsync`): отмена `AbortController`, защита от гонок, ключ кэша, `retry`. Не пиши `fetch` в `useEffect` компонента.
- Поиск «по набору текста» — через debounce и минимальную длину запроса.
- Любой экран с данными обрабатывает все состояния: `idle`, `loading`, `error` (с повтором), пустой результат, успех.
- Глобальное состояние — Zustand-store; действия, зависящие друг от друга (смена запроса сбрасывает страницу), описывай внутри store, а не в компонентах.

## 5. Чек-лист перед тем как сказать «готово»

1. В View нет логики (см. раздел 1).
2. У каждого presenter есть причина существовать; пустых нет.
3. Ни один файл не длиннее 120 строк.
4. Новый компонент лежит в своей папке и в правильной ветке дерева.
5. Типы не продублированы.
6. `npm run lint` и `npm run build` проходят без ошибок.
7. Новое правило, возникшее на практике, добавлено в «Добавлено на практике» в ARCHITECTURE.md.

## 6. Пример (образец в проекте)

`src/ShowsExplorer/ShowList/ShowCard/`:

```tsx
// usePresenter.ts — вся подготовка данных
export function usePresenter(show: Show) {
  return {
    posterUrl: show.image?.original ?? null,
    year: show.premiered?.slice(0, 4) ?? null,
    ratingLabel: show.rating.average === null ? null : `★ ${show.rating.average}`,
    genresLabel: show.genres.join(' · '),
  }
}

// ShowCard.tsx — только разметка
export default function ShowCard({ show }: Props) {
  const { posterUrl, year, ratingLabel, genresLabel } = usePresenter(show)
  return (/* JSX */)
}
```
