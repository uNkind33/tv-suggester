# Правила архитектуры

**Simple Architecture = Clean Architecture + VIPER.** Слои разделены по ответственности (Clean), каждый экран собран по схеме View + Presenter (VIPER). View === JSX + `usePresenter()`.

1. Слои: View — только JSX и вызов `usePresenter`; Presenter берёт данные из хранилища и готовит их; логика — в хуках с понятными именами.
2. Файл — не больше 120 строк. Исключений нет.
3. Дерево папок повторяет иерархию компонентов; у каждого компонента своя папка (view + presenter); вложенность не ограничена.
4. `components` включает переиспользуемые ниже по дереву компоненты: общие для всего приложения — в `src/components`; общие для одной ветки — в `components` этой ветки (на уровне их ближайшего общего предка); используемый одним родителем — подпапкой внутри этого родителя, а в `components` не лежит.
5. `SearchBar/SearchBar.tsx`, `SearchBar/usePresenter.ts`.
6. Архитектура — абстракции, а не инструменты; правила не ослабляем ради скорости.

## Добавлено на практике
7. Инфраструктурные папки `api/`, `store/`, `lib/`, `hooks/` лежат в корне `src` рядом с `components`.
8. Стили — CSS Modules рядом с компонентом (`ShowCard/ShowCard.module.css`).
9. `usePresenter.ts` создаём только если есть что готовить (данные из хранилища, форматирование, обработчики). Пустой presenter-«прокладка» не нужен: чисто декоративные компоненты (`ShowListSkeleton`, `StateMessage`) живут без него. Как только в View появляется логика — выносим её в presenter.
10. Типы, общие для нескольких файлов (например `AsyncStatus`), объявляются один раз в месте-владельце и импортируются; копировать тип нельзя.
